一、請求一路怎麼走（從進站到出站）

Client 發 API 請求（例：POST /api/auth/login，Body 是 LoginDto）。

Middleware（中介軟體）前置區

（正式環境）ApiExceptionMiddleware：負責攔所有未處理例外，把它們轉成
ServiceResult<object?>.Fail("...") + 正確 HTTP 狀態碼（401/500…）。

（開發環境）你用 DeveloperExceptionPage() 看除錯頁；也可改成同樣走 ApiExceptionMiddleware。

MVC Model Binding + FluentValidation

ASP.NET Core 將 JSON 反序列化成 LoginDto。

FluentValidation 自動跑 RegisterDtoValidator/LoginDtoValidator ... 規則。

若有欄位錯誤 → ModelState 會被標記為 invalid（400）。

（重點）統一 ModelState 的 400 格式

你在 Program.cs 用 ConfigureApiBehaviorOptions.InvalidModelStateResponseFactory = ...。

這個掛點會在 MVC 要回 400 前觸發，我們把 ModelState 的錯誤轉成：

{
  "success": false,
  "errorMessage": "欄位驗證錯誤",
  "errors": [{"field":"Email","message":"電子信箱不可空白"}, ...],
  "data": null
}


直接回 400 BadRequest，Controller 的 Action 根本不會被呼叫。

Controller Action（只有通過驗證才會進來）

你在 Action 裡呼叫 Service：var result = await _service.LoginAsync(...)

Service 回的是 ServiceResult<T>（統一格式），Controller 用
return this.ToHttpResult(result); 把成功/失敗對應到正確狀態碼並回相同包裝。

Service（商業邏輯）

成功 → ServiceResult<T>.Ok(data)，data 是乾淨的 DTO（不再含 ok/error 欄位）。

失敗 → ServiceResult<T>.Fail("錯誤訊息") / Fail("訊息", fieldErrors)

重點：成功/失敗的語意只在外層 ServiceResult.Success，data 永遠只放資料。

回傳到 Client

成功（例如登入）→ 200 OK +

{"success":true,"errorMessage":null,"errors":null,"data":{"accessToken":"...","expiresIn":3600,"userName":"..."}}  


註冊成功 → 201 Created（你用 ToHttpResult(result, 201) 指定）。

欄位驗證失敗 → 400（由 InvalidModelStateResponseFactory 統一包）。

未授權/Token 失效 → 401（由 ApiExceptionMiddleware 或你在 Controller 明確回）。

其他未處理例外 → 500（由 ApiExceptionMiddleware 統一包）。


******** 好用的 FluentValidation *********

1. 安裝必要套件
dotnet add package FluentValidation.AspNetCore

2. 設定 Program.cs（註冊 FluentValidation）
builder.Services.AddValidatorsFromAssemblyContaining<OrderUpdateDtoValidator>();    //只要註冊其中「任一個」即可掃描整個專案的 Validators
builder.Services.AddFluentValidationAutoValidation();

3. 撰寫 Validator 類別
   每個 DTO 對應一個 Validator：
   * UserCreateDto.cs
   public class UserCreateDto
   {
      public string Username { get; set; }
      public string PostalCode { get; set; }
      public string City { get; set; }
      public string District { get; set; }
   }

   * UserCreateDtoValidator.cs
   using FluentValidation;

   public class UserCreateDtoValidator : AbstractValidator<UserCreateDto>
   {
      public UserCreateDtoValidator()
      {
         RuleFor(x => x.Username)
               .NotEmpty().WithMessage("使用者名稱不可空白")
               .MaximumLength(20).WithMessage("不能超過 20 個字");

         RuleFor(x => x.PostalCode)
               .NotEmpty().WithMessage("郵遞區號不可空白")
               .Matches(@"^\d{3}$").WithMessage("格式需為 3 碼數字");

         RuleFor(x => x.City)
               .NotEmpty().WithMessage("縣市不可空白");

         RuleFor(x => x.District)
               .NotEmpty().WithMessage("鄉鎮區不可空白");
      }
   }

4. 在 Controller 中使用（自動觸發）
   [HttpPut("{id}")]
   public async Task<ActionResult> Update(int id, [FromBody] UserUpdateDto dto)
   {

      var result = await _service.UpdateAsync(id, dto);
      if (!result.Success)
      {
         return NotFound(result);
      }

      return NoContent();
   }

5. 解釋 Middleware 的作用流程：
ASP.NET Core 處理請求時：
會自動執行 FluentValidation 驗證（因為你有註冊 AddFluentValidationAutoValidation()）
驗證失敗時，ASP.NET Core 預設會產生一個 400 BadRequest 回應，內容是 ValidationProblemDetails 格式。
你的 ValidationExceptionMiddleware：
攔截這個 400 回應
解析內部的 ValidationProblemDetails（包含欄位錯誤）
把它轉成你自己的格式 ServiceResult.Fail(...) 並統一輸出
這就是為什麼你不需要寫 if (!ModelState.IsValid)，但還是能得到統一格式的錯誤訊息
